# API design review

Reviewed 2026-10-07 against the initial release and the city-schema correction. The source is [Thomas Karatzas's API design thread](https://x.com/karatzas_thomas/status/2105691392169394384). The six main advice posts include nine distinct tips. The author also recommends layering and composition in a reply. The decisions below are an assessment of Weather Bridge, not claims made by the author about this project.

## Decisions by tip

## Human and agent usability

[Agentic] MCP tools publish input/output schemas and typed, actionable results. A caller could previously reject a padded valid city or accept a padded one-character name because the schema counted raw characters. The shared pattern correction removes that specific mismatch. Rust contract tests compare every MCP city pattern with the REST pattern evaluated by JavaScript, and both languages consume the same boundary examples.

[DevUX] `README.md` provides the run and search path; `docs/reference.md` defines limits and failures. The corrected pnpm statements now agree with the build configuration and generated headers. Rust method documentation states which calls can use the network.

[Automation] The schema pattern explicitly matches each Unicode character, including a UTF-16 surrogate pair when the JavaScript Unicode regex flag is absent. The same boundary cases pass with and without that flag. This removes the need for callers to supply a separate regex flag. The pattern checks trimmed length only; runtime city resolution still validates syntax and existence.

## Verification

The regression data are in [city-query-inputs.json](../tests/fixtures/city-query-inputs.json). The check set includes generated-artifact freshness, Rust contracts, frontend behavior/type checks, offline transport smoke, browser fixtures, minimum-Rust compilation, and dependency policy. NWS fetching and parsing are unchanged; these fixture checks do not prove live upstream availability.
